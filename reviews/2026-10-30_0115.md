## 4. 보완할 점 🧩 (공통, 팀장이 정리)

- **공통 디자인 부품이 화면마다 따로 있다.** 솜이 그림, 밤하늘 장면, 뒤로 가기 헤더, 선택 카드가 p3·p4·p5 폴더에 각자 복사돼 있다. → 팀장이 `DESIGN.md`(디자인 규칙)와 공통 컴포넌트로 모은다. 그 뒤로는 **공통 부품을 가져다 쓰고, 새로 그리지 않는다.**
- **음료 함량이 전부 임시값**이라 화면에 "(함량 추정)"이 뜬다.
- **대회장 좌표가 0, 0**이라 실제 대회장에서 카페 알림이 안 뜬다.

## 6. 지켜야 할 규칙 📏

- main에 push하지 않는다. **자기 브랜치(p1~p5)에만** push한다.
- **자기 화면 폴더만** 고친다. 공통(lib/, components/, prisma/, Docker, docs/, globals.css)은 팀장에게 요청한다.
- **버튼 글자는 `lib/copy.ts` 그대로.** 채점 테스트가 그 글자를 찾아 누른다. 바꾸고 싶으면 팀장에게.
- **기획에 없는 기능은 만들지 않는다.** 하고 싶은 기능은 아래 "기획 손볼 후보"에 적는다.
- 색·글꼴·간격은 `app/globals.css` 토큰만 쓴다. 그림은 `public/`의 공통 에셋을 쓴다.
- push 전 4가지: `npm run typecheck` · `npm test` · `npm run build` · `npm run scope -- p번호`
  - `AGENTS.md`, `tsconfig.json`이 scope에 걸리는 건 `npm run dev`가 자동으로 고친 것이라 무시한다.
- 09:00 기능 동결 뒤에는 push를 멈춘다.
